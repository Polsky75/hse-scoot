# Применённый принцип
Наиболее ярко был применён принцип SOLID "Dependency Inversion". Для работы с оборудованием и транспортом используются универсальные интерфейсы, поэтому для учёта энергопотребления зарядных станций не пришлось перерабатывать весь код. Также принцип используется для ввода и вывода, чтобы в будущем была возможность добавить новые реализации.

# Ограниченный принцип
Касательно фабрик ParseTransportKind и ParseEquipmentKind ограничен Open-Closed Principle. Для добавления нового вида транспорта или типа оборудования потребуется добавить новую константу и ветку switch в соответствующем файле. Так пришлось поступить, потому что количество потенциально доступных видов транспорта и оборудования довольно ограничено, а по-настоящему open-closed система нагружала бы код.

# Расширение кода
При добавлении нового вида транспорта необходимо будет добавить новый файл в домен, константу и ветку switch в ParseTransportKind/ParseEquipmentKind, категорию и название на русском языке в item_category, пункт в transportCatalog (отделяющий использующий энергию транспорт от неиспользующего) и префикс в numberAllocator (выдающий ID по умолчанию).
При добавлении сотрудника нужно будет написать новый интерфейс IEmployee и новую структуру Employee. Код не сломается - указатели на хранимую технику сотрудник может хранить в специальном поле.
Ради добавления складов желательно будет переписать систему хранения имущества, так оно будет храниться по отдельности.
