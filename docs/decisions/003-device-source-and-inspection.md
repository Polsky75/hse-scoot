# 003. Порт источника данных и техосмотр перед постановкой на учёт

- **Дата:** 2026-10-25
- **Статус:** принято

## Контекст

Список начальных устройств и устройств, поставляемых на учёт, должен
приходить из текстового файла. Обращаться к файлу напрямую из прикладного
кода нельзя: впоследствии параметры должны задаваться другими способами,
например через JSON. Кроме того, новое устройство можно поставить на учёт
только после техосмотра.

## Решение

- В `internal/source` объявлен порт `Source` с методом `Load()`
  и входные типы `DeviceSpec`, `EquipmentSpec`/`Dataset`. `Dataset`
  разделён на `Registered` (уже на балансе), `Incoming` (поставляются
  на учёт) и `Equipment` (снаряжение).
- `internal/source/textfile` — единственный адаптер, который открывает файл,
  разбирает секции и валидирует строки, включая лёгкость использования.
  Домен и сценарий не импортируют `os` для загрузки списка.
- `fleet.Service.Sync` — прикладной сценарий: загрузить датасет,
  восстановить начальный парк, добавить снаряжение, для каждого нового
  устройства создать сущность, провести техосмотр и добавить прошедшее
  в инвентарь.
- `inspection.Inspector` оценивает состояние по шкале 0..100; порог по
  умолчанию — 70. Устройство с меньшей оценкой получает
  `inspection.ErrFailed` и не регистрируется.
- Начальный парк уже стоит на учёте, поэтому повторно не инспектируется.
- Ошибка загрузки источника прерывает запуск; ошибка отдельного нового
  устройства попадает в `RegistrationResult` и не мешает остальным.

## Альтернативы

- **Читать файл в `main` или `fleet`.** Быстрее на старте, но нарушает
  требование «не обращаться напрямую» и делает замену формата правкой
  сценария.
- **Сразу реализовать JSON-адаптер.** Порт уже позволяет добавить его
  позже; второй парсер без согласованного формата и потребителя —
  преждевременная работа.
- **Техосмотр внутри конструктора сущности.** Смешивает проверку
  инвариантов предметной области с рабочим процессом и не позволяет
  менять политику осмотра независимо.
- **Инспектировать и начальный парк при каждом запуске.** Начальные
  устройства уже приняты на учёт; повторный осмотр изменил бы смысл
  секции `[registered]`.

## Последствия

- JSON, БД или другой источник подключается реализацией `Source`
  и одной строкой в `di.NewWithSource`; `fleet`, `console` и домен
  не меняются.
- Формат текстового файла и его ошибки локализованы в адаптере.
- Порог техосмотра задаётся при сборке контейнера; более сложные правила
  можно добавить в инспектор, не трогая сценарий регистрации.
- Парк хранится в памяти на время запуска; для постоянного хранения
  потребуется отдельный репозиторий.
