# 006. Инвентарные номера, категории, счёт и отчёт

- **Дата:** 2026-10-25
- **Статус:** принято

## Контекст

Нужно считать вещи на учёте: все вещи, транспорт, самокаты и наколенники.
У каждой вещи должен быть инвентарный номер и категория. Отчёт со списками
всей техники, всего транспорта и транспорта для новичков должен выводиться
в консоль или файл, с заделом на другие способы вывода.

## Решение

- В `IInventoriable` добавлены `GetInventoryNumber() string`
  и `GetCategory() ItemCategory`. Внутренний `inventoryItem` хранит номер
  и категорию; конструкторы проверяют непустой номер.
- Введён `ItemCategory` с константами для всех видов техники и снаряжения,
  а также `Label()` для человекочитаемого вывода.
- Пакет `internal/report` собирает `Document` из среза
  `[]domain.IInventoriable`:
  - `Counts` — всего, транспорт, самокаты, наколенники;
  - `AllItems` — вся техника;
  - `Transport` — только `ITransport`;
  - `BeginnerTransport` — транспорт, отобранный для новичков.
- Счёт вынесен в функции `CountAll`, `CountTransport` и `CountCategory`;
  отчёт использует их, а не дублирует циклы.
- Вывод описан интерфейсом `report.Output` с реализациями
  `ConsoleOutput` и `FileOutput`. Фабрика `report.NewOutput` выбирает
  способ по имени. Новый способ добавляется реализацией интерфейса
  и веткой фабрики.
- `console.App` выполняет сценарий, печатает служебный статус регистрации
  и передаёт готовый `Document` в выбранный `Output`.
- В CLI добавлены флаги `-report` (`console`/`file`) и `-report-path`.
- Входные DTO источника переименованы на `InventoryNumber`, текстовый
  адаптер проверяет уникальность номеров между всеми секциями.

## Альтернативы

- **Печатать отчёт прямо в `console`.** Не даёт выбрать файл и не оставляет
  точки расширения для других способов вывода.
- **Отдельная функция на каждый счётчик.** `CountCategory` уже покрывает
  самокаты и наколенники; отдельные функции дублировали бы обход.
- **Библиотека отчётов или шаблонизатор.** Для трёх секций и текстового
  вывода это лишняя зависимость.
- **Сразу делать JSON-вывод.** Требуется только текстовый отчёт;
  интерфейс `Output` позволяет добавить JSON позже без переделки счёта.
- **Хранить отчёт в домене.** Домен не должен знать о форматировании
  и файлах; `report` — прикладной слой представления.

## Последствия

- Инвентарный номер стал явной частью контракта и используется в отчёте;
  старые `GetID`/`ID` заменены.
- Категория хранится в вещи, поэтому отчёт не делает type switch по
  конкретным типам.
- Новый способ вывода не затрагивает `fleet` и `domain`; новый счётчик
  категории — одна строка с `CountCategory`.
- Ошибки записи файла возвращаются наверх и не подменяются успехом.
- Отчёт строится по текущему инвентарю; отклонённый техосмотром транспорт
  в него не попадает, но остаётся в служебном статусе.
